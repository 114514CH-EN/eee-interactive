Lab 1 · Task 1 · Build an Encoder · bits = encodeSource(seq, dict)

编码器：查表、按顺序拼起来——难点在「不要在循环里一点点加长 bits」

huffmandict 只给码表：dict{i,1} 是符号，dict{i,2} 是码字向量（比如 [1 1 0]），不给比特流。encodeSource 要做的就是对 seq 里的每个符号查到码字、按顺序接成一行 0/1。改码表或序列看比特流怎么变；输入一个码表里没有的符号（比如 E），看一个有用的 error() 应该说什么。


  

  
为什么 10,000 个符号会慢：每次「加长」都要整段复制

  
在循环里写 bits = [bits dict{k,2}];，MATLAB 每次都要新开一块更长的内存，把已有的比特全部复制过去。第 k 次复制大约 k·L̄ 个元素，加起来约 L̄N²/2——N 翻倍，时间变 4 倍。先算出总长度一次分配好（预分配），每个比特只写一次，总共 L̄N 次。

  
N边循环边加长预分配
点上面的按钮开始（几秒钟）

  
MATLAB 思路（不是完整答案）：① 查表：用 ismember 一次找出每个符号在 dict(:,1) 里的行号 idx；找不到的位置用 error('encodeSource:unknownSymbol', 'Symbol "%s" at position %d is not in the dictionary', …) 报出来——要说清哪个符号、第几个。② 预分配：每个码字长度 len = cellfun(@numel, dict(:,2))，总长 sum(len(idx))，先 zeros(1, 总长)，再用一个位置指针往里填；或者用逗号分隔列表一次拼接 [dict{idx,2}]（只分配一次）。③ 两个坑：Live Script 里 huffmandict(n, p) 的符号是数字 1–4，不是 'A'–'D'，要么用 huffmandict({'A','B','C','D'}, p)，要么先把字母映射成数字；'A B C D A A' 这样带空格的字符向量里，空格本身也是一个符号，会触发你的 error()。






  
Lab 1 · Task 2 · Build a Decoder · seq = decodeSource(bits, dict)

  
解码器：一位一位读，凑成码字就输出并清空——码表不是前缀码时，错误往往是「看起来正常」的

  
规定的做法：从左到右每读一位就把它加进缓冲区，缓冲区和某个码字一样就输出那个符号并清空；不许往后看、不许分隔符、不许传长度。前缀码保证「第一次匹配就是对的」。把 C 的 110 改成 11（它变成了 D = 111 的前缀），同一条消息再编码、再解码，看会怎样。

  

  

  

  

  

  

  

  

  
码表检查器：解码前先确认是前缀码

  
    
  
    想一想：报错、卡死、给出看似正常的错数据，哪种在真实接收机里最危险？（点开看思路）
    
    看似正常的错数据最危险。报错（比如末尾剩下凑不成码字的比特）至少让接收端知道出了问题，可以重传或丢弃；卡死也会被看门狗或超时发现。但贪心匹配到一个更短的码字后，后面的切点全部错位，输出的却是一串完全合法的符号——符号个数可能一样、可能不一样，接收端没有任何办法发现，错数据会被当成真数据继续用。上面「随机发 2000 条消息」可以看到，同一本坏码表下，有的消息会报错，有的不会：靠「解码时报没报错」来判断码表对不对是靠不住的，所以要在用之前检查码表。
    
    
    什么时候会卡死：规定的「读一位再查表」不会卡死；但如果实现成「先查表、匹配不上才读下一位」，一个空码字 [] 会让解码器原地不停地输出它；用 while 循环等待「剩余比特以某个码字开头」的写法，在尾巴凑不成码字时也会永远等下去。
    
  
    
  
    检查器的思路：把码字当成字符串（比如 strjoin(string(c),"")）按字典序排序，只需比较相邻两个：如果 a 是某个 b 的前缀，排序后夹在 a 和 b 之间的串也都以 a 开头，所以 a 一定是它紧后面那个串的前缀（重复码字也会相邻）。再加上：不能有空码字、只能含 0 和 1。Kraft 和 K = Σ2−ℓ ≤ 1 是唯一可译的必要条件，可以顺手算，但 K ≤ 1 并不保证前缀性（比如 A=0、B=01 的 K = 0.75，却不是前缀码）。
    

    


    
  
    Lab 1 · Task 3 · Compress Real Data
    
  
    压缩一段真实文本：H、测得的 L、ASCII 的 8 bit，差距各来自哪里
    
  
    做法和讲义给的 MATLAB 代码一样：fileread 读进来，double() 变成字符编码，unique 找出用到的符号，accumarray 计数得到经验分布 p，再算 H(x)、建 Huffman 码表、编码整个文件。可以直接粘贴你的 mytext.txt，或者读取本地文件（只在浏览器里处理，不上传）。
    
  
    
  
  
    
  
    
  
  
    每个符号的计数、p、−log₂p、码长和码字（按出现次数排序）
    
  
    想一想：为什么对 ASCII 的压缩比比 η 看起来好得多？（点开看思路）
    
    η = H/L 只衡量「在已经知道只有这 |𝒳| 个符号的前提下，离最优还差多少」，所以总是 95% 以上。8 bit 的 ASCII 基线是在为 256 种可能的字符付钱，而你的文本只用到其中几十种：光是「只给用到的符号编号」就能从 8 bit 降到 ⌈log₂|𝒳|⌉ bit，这一截和概率分布无关，η 根本没算进去。右上图把 8 → L 的下降拆成三段：字母表变小、按概率分配、整数码长的代价。
    
    
    谁离 x = y 线最远：码长只能是整数。出现一次的字符 −log₂p 是十几，Huffman 往往给得更短（在线下方）；最常见的空格 −log₂p ≈ 2.6，只能给 3（在线上方，多付了零点几 bit，但乘以很大的 p，对 L 的影响反而最大）。Huffman 不会让每个点都靠近 x = y，它只保证 Σ piℓi 最小。
    
  
    
  
    和 MATLAB 结果对不上时：① 记事本保存的文件换行是 \r\n，double(txt) 里会多出字符 13，勾上上面的选项再比；② huffmandict 在概率相同的符号之间分配码长的方式可能和这里不同，个别符号的码长会差 1，但平均码长 L 一定一样（所有 Huffman 码都是最优的）；③ L 用测得的总比特数 ÷ 符号数，和 Σ piℓi 相等，因为 p 就是从这份文本数出来的。
    

    


    
  
    Lab 1 · Task 4 + Extension · When the Statistics are Wrong
    
  
    用前一半建码表、编码后一半：多出来的比特就是「统计不准」的代价
    
  
    编码器从来不知道真实的 p，只能用已经见过的数据估计。用 Task 3 的文本（在上一个面板里改），前面一部分数出 p 建 Huffman 码表，拿它编码剩下的部分，和剩下部分自己的熵 H 比。后半出现了前半没有的字符时，Task 1 的编码器会直接 error()；Extension 让你想办法处理它，下面可以切换几种办法比较。
    
  
    
    
    
    
    
  
    
  
    后半部分的熵 H(q)
    用后半自己的统计建 Huffman
    用前半的码表测得 L
    多花 L − H(q)
    其中理论代价 D(q‖p)
    
  
    
  
    想一想：为什么 L 比 H 大，大多少？（点开看思路）
    
    用为 p 设计的码去编码统计为 q 的数据，理想（码长可以是小数）时每个符号要 −log₂pi bit，平均就是交叉熵 H(q, p) = Σ qi(−log₂pi) = H(q) + D(q‖p)。D(q‖p) = Σ qilog₂(qi/pi) 叫 KL 散度，≥ 0，两个分布越不像越大；再加上整数码长的那一点点代价，就是测得的 L − H(q)。训练数据越少，p 估得越不准，D(q‖p) 越大（左图往左走）。只要后半有一个前半没见过的字符，pi = 0，−log₂pi = ∞：固定码表根本编不出来，不是「多花一点」的问题。
    
    
    Extension 的几种办法：转义符给「没见过的字符」留一个码字，后面跟它的原始编码，代价是每个新字符多花一个 ESC 加 8 bit；加一平滑让 256 个字节值都有码字，代价是每个已知字符的码字略长；自适应让编码器和解码器按同样的规则一起更新统计（解码器能同步，因为它看到的数据和编码器一样），越编越准。

    实验 1 · Week 3 · Huffman Coding Tutorial Question / Further Thoughts
    
  
    收到一串比特，怎么切开？前缀码只有一种切法
    
  
    讲义 Tutorial：码表 A=0、B=10、C=110、D=111，收到 00100111010，能唯一解码吗？任何码字都不是别的码字的前缀，所以从左往右读，凑够一个码字就切一刀，不会切错。点任意一个比特把它翻转，模拟信道误码，看变长码会怎样「失步」。再换成讲义里那个「打破熵极限」的码 A=0、B=1、C=00、D=01，看 0001 有几种读法。
    
  
    
  
    
    
    
    
    
  
    
  
    
  
    
  
    
  
      
  
      平均码长 L̄ = Σ p·ℓ
      信源熵 H（0.55 / 0.3 / 0.1 / 0.05）1.544 bit
      效率 H / L̄
      这一串
      
  
      Tutorial 答案：00100111010 = 0|0|10|0|111|0|10 = AABADAB，唯一。问题：一个比特错了，后面的切点全跟着错（误码传播），甚至解出的符号个数都变了；定长码错一位只坏一个符号。好处：平均 1.6 bit/符号，比定长的 2 bit 省 20%，离熵 1.544 只差一点。A=0 B=1 C=00 D=01 平均只要 1.15 bit，看起来低于熵，但 0001 有好几种读法，根本没法用——任何看似打破熵极限的码都是这样。
      

      


      
  
      实验 2 · Week 3 · Source Coding: Further Thoughts
      
  
      把几个符号打包再编码：平均码长从上方逼近熵
      
  
      单个符号编码时每个码字至少 1 bit，信源很偏时浪费很大（比如 0.9 / 0.1 的二元信源熵只有 0.469 bit，单独编码却要 1 bit）。把 n 个符号当成一个「大符号」做 Huffman，平均每个原符号的比特数 L̄n/n 落在 H 和 H + 1/n 之间，n 越大越接近熵。这不是打破熵极限，只是换了个统计模型。
      
  
      
  
      
    
      
  
      
  
      分组概率Huffman 码字
      
  
      熵 H
      n = 1：L̄₁
      当前 n：L̄n/n
      效率 H/(L̄n/n)
      
  
      为什么有上界 H + 1/n：对 n 个符号的分组，最优码满足 nH ≤ L̄n < nH + 1（多出来的不到 1 bit 来自码长必须是整数），除以 n 就得到每个原符号的界。均匀分布时 H = 2 bit 正好是整数，n = 1 就已经 100%。真实文本里相邻符号还不独立（q 后面几乎总是 u），zip 之类的压缩利用的就是这种相关性。
      

      


      
  
      实验 3 · Generic Models & Channel Capacity · Useful Equations
      
  
      香农容量 C = B log₂(1 + S/N)：带宽是线性的，信噪比是对数的
      
  
      C 是在带宽 B、信噪比 S/N 下能做到无差错传输的最高比特率。左图固定 B 看 S/N：高信噪比时每多 3 dB 只多 1 bit/s/Hz。右图固定信号功率 S 和噪声谱密度 N₀（N = N₀B）只加带宽：噪声也跟着变大，容量趋于上限 1.44·S/N₀。
      
  
      
  
      
    
      
    
      
  
      
  
      
  
      S/N（倍数）
      容量 C
      频谱效率 C/B
      带宽翻倍（N₀ 不变）/ S/N 翻倍
      带宽无限大时的上限 S/(N₀ ln2)
      
  
      换底：计算器没有 log₂ 时用 C = B·log₁₀(1+S/N)/log₁₀2（讲义写法）。记两个数：S/N = 0 dB 时 C = B；S/N 很大时 C ≈ B × S/N(dB)/3.01。电话线 3.1 kHz、30 dB：C = 3100 × log₂1001 ≈ 30.9 kbit/s，这就是老式拨号调制解调器卡在 ~33.6 kbit/s 附近的原因。
      

      


      
  
      实验 4 · Wireless: Antennas & Propagation · Useful Equations
      
  
      链路预算：自由空间每十倍距离掉 20 dB，贴地传播掉 40 dB
      
  
      自由空间 Pr = PtGtGr(λ/4πd)²；在导电地面上方，直射波和地面反射波干涉，远处变成 Pr = PtGtGr(hthr/d²)²。用 dB 写就是一路加减。蓝线自由空间，橙线是地面双径的精确干涉（细线）和讲义近似（粗虚线），两者在 d ≫ 4πhthr/λ 后重合。绿线是接收灵敏度。
      
  
      
  
      
    
      
    
      
    
      
    
      
    
      
    
      
    
      
    
      
  
      
  
      
  
      波长 λ = c/f
      自由空间路径损耗 20log(4πd/λ)
      Pr：自由空间 / 地面双径
      余量（自由空间 − 灵敏度）
      最远距离：自由空间 / 双径
      转折距离 4πhthr/λ；接收口径 A = Gλ²/4π
      
  
      为什么频率高损耗大：不是空气「吸收」得多，而是同样增益的天线在高频时口径 A = Gλ²/4π 更小，接住的能量更少（理想天线 D = 4πA/λ²）。地面双径：远处直射波和反射波几乎等长、反射又反相，二者几乎抵消，所以按 1/d⁴ 衰减，而且和频率无关；把天线架高（hthr 变大）比加功率有效得多——这就是基站要上铁塔的原因。卫星预设里 d = 36 000 km，自由空间损耗约 205 dB，要靠两端的大锅天线补回来。
      

      


      
  
      实验 5 · Transmitting Analogue Signals by Digital Methods · Useful Equations
      
  
      量化噪声：每多 1 bit，SQNR 多 6 dB
      
  
      先按 fs > 2Fmax 采样，再把 −A/2 … A/2 等分成 N = 2p 级，每个样本取最近的一级。蓝线是原信号，橙色台阶是量化后的样本，下面红线是量化误差（最大 ±Δ/2）。满幅正弦的 SQNR = 3N²/2，即 6.02p + 1.76 dB；信号比满幅小多少 dB，SQNR 就少多少 dB。
      
  
      
  
      
    
      
    
      
    
      
  
      
  
      
  
      量化级数 N = 2p / 级间距 Δ = A/N
      SQNR 公式 6.02p + 1.76 + 电平
      SQNR 实测（大量样本）
      比特率 fs × p
      
  
      公式从哪来：误差在 ±Δ/2 内均匀分布，功率 Δ²/12；满幅正弦功率 (A/2)²/2 = A²/8；相除并代入 Δ = A/N 得 3N²/2，取 10log₁₀ 就是 1.76 + 6.02p。p = 1 或信号很小时误差不再「均匀」，实测会偏离公式。电话 8 kHz × 8 bit = 64 kbit/s，正好是一路数字电话（PCM）的速率。
      

      


      
  
      实验 6 · The Effect of Noise · Useful Equations
      
  
      噪声里判 0 还是 1：误码率就是高斯尾巴的面积
      
  
      发送电平（单极性 0 / A 或双极性 ±A）加上标准差 σ 的高斯噪声，接收端和门限 Vth 比较。把门限归一化成 xth = (Vth − 电平)/σ，错判概率 = 1 − Φ(xth)，就是阴影面积。点「发 2000 个比特」看实际数出的错误和理论是否一致。
      
  
      
  
      
    
      
    
      
    
      
    
      
  
      
  
      
  
      
  
      发 0 判成 1：1 − Φ(xth)
      发 1 判成 0
      总误码率（等概率）
      实测（2000 bit）
      电平间距 / σ
      
  
      怎么查表：单极性 0/1 V、σ = 0.25 V、门限 0.5 V：xth = (0.5 − 0)/0.25 = 2，P = 1 − Φ(2) = 0.0228；两边对称，总误码率也是 0.0228。门限偏离中点时，一边的尾巴缩小、另一边涨得更快，总和变大。双极性 ±1 V 的间距是 2 V，相当于 xth = 4，误码率降到 3×10⁻⁵——代价是平均功率更大。真正决定误码率的是「电平间距 ÷ 噪声」。
      

      


      
  
      实验 7 · Digital and Analogue Filters · Useful Equations
      
  
      Butterworth 通带最平，Chebyshev 用通带波纹换更陡的过渡带
      
  
      Butterworth：|T|² = 1/[1 + (ω/ωc)2n]，通带没有起伏，ωc 处 −3 dB。Chebyshev：|T|² = 1/[1 + ε²Cn²(ω/ωp)]，通带在 1 和 1/(1+ε²) 之间波动 n 次，换来过渡带更陡。设一个阻带指标，看两种各需要几阶。
      
  
      
  
      
    
      
    
      
    
      
    
      
  
      
  
      
  
      ε = √(10波纹/10 − 1)
      ωs 处衰减：Butterworth / Chebyshev
      满足指标的最小阶数：Butterworth / Chebyshev
      远处斜率
      
  
      远处都是 −20n dB/十倍频：n 阶滤波器在 ω ≫ ωc 时都按 1/ωn 衰减，Chebyshev 的优势在过渡带——同样阶数下，远处它比 Butterworth 多出约 20log(2n−1ε) 的衰减（ε 小时可能反而不如 Butterworth）。阶数公式：Butterworth n ≥ log(10A/10 − 1)/(2 log(ωs/ωc))，Chebyshev n ≥ cosh⁻¹(√(10A/10 − 1)/ε)/cosh⁻¹(ωs/ωp)。
