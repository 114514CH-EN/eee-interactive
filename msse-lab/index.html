实验 2 · Lecture 1 Basic Datatypes / Real numbers

同一个算式，Python 2 和 Python 3 的答案不一样

讲义 Real numbers 那页把 7 / 3 * 1.2 + 3 / 2 一步步算成 3.4——那是 Python 2 的规则：两个整数相除做整除。你们实验用的是 Python 3：/ 永远得到 float，整除要写 //。下面按 Python 的优先级和从左到右的顺序，一步只算一个运算，两种规则并排。

支持整数、小数、括号和 + − * / // % **。

      记住四条：① 3 里 / 是真除法，// 是向下取整（往 −∞ 取，所以 -7 // 2 = -4），% 的符号跟除数一致（-7 % 2 = 1），总有 a == (a // b) * b + a % b。② int 和 float 混算结果是 float，「逐个运算符」转换。③ ** 比负号优先，-2 ** 2 = -4；而且右结合。④ Python 的 int 没有位数上限（2 ** 100 精确），float 是双精度，0.1 + 0.2 ≠ 0.3。讲义的 z = 5 / 2 # Answer is 2 在 Python 3 里是 2.5。

      实验 5 · Module Overview · System development lifecycle / “Vee” process
      
  
      Vee 模型：左边一层层分解设计，右边一层层对着设计去测
      
  
      讲义：Vee 过程把开发看成「设计」和「测试」两条腿，中间用验证（verification）和确认（validation）连起来保证质量。左腿自顶向下（top-down，分解），底部写代码，右腿自底向上（bottom-up，组装）测试；每个测试阶段对照的是同一高度的设计文档。点任意一格看它做什么，例子是一个联网的智能温控器。
      
  
      
  
      
  
      两个容易混的词：verification 问「我们是不是把东西做对了」（符合规格书，右腿下面三层主要在做这个）；validation 问「我们是不是做了对的东西」（真的满足用户需要，最上面的验收测试）。越早发现的错误越便宜：需求错了要到最后的验收才暴露，整条 V 都要返工。课程后半段的 SysML 就是左腿用的建模语言：需求图、块定义图 / 内部块图（结构）、活动图 / 状态机图（行为）。
